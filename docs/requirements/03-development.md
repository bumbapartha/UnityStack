## Requirements

| ID     | Priority | Requirement                                                                                                                                                                                                                                                                                                                                                                               |
| ------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-133 | P0       | **New.** Sprint planning: the AI proposes which stories go into the next sprint, based on priority, dependencies and team capacity; the user adjusts and approves; the sprint is created in the project-management tool through its adapter (OpenProject first, Jira later). "Pick a story" then shows stories from the current sprint, and accepted bugs go to the backlog for planning. |
| FR-116 | P0       | **New.** For a story, the developer agent proposes code changes and matching tests together, on a branch, after reading the linked requirement, story, ADRs and repository conventions.                                                                                                                                                                                                   |
| FR-018 | P0       | Treat approved GitHub content as the canonical version of durable, reviewable SDLC artifacts.                                                                                                                                                                                                                                                                                             |
| FR-019 | P0       | AI-generated changes are made on branches and proposed through PRs; no direct AI push to protected branches.                                                                                                                                                                                                                                                                              |
| FR-021 | P0       | Validate generated artifacts against schemas and project rules before creating a PR.                                                                                                                                                                                                                                                                                                      |
| FR-022 | P0       | Preserve actor, prompt/run reference, source requirement, artifact version, PR URL and approval status for audit.                                                                                                                                                                                                                                                                         |
| FR-066 | P1       | Support configurable optional additional reviewer approval per organisation or repository. _(Sole user for now; see [D-7](../open-questions.md).)_                                                                                                                                                                                                                                        |
| FR-067 | P1       | Permit automatic merge only where policy and branch protection allow and all required checks pass. _(Was P0.)_                                                                                                                                                                                                                                                                            |
| FR-024 | P1       | Detect and reconcile changes made directly in connected tools to prevent uncontrolled divergence from Git.                                                                                                                                                                                                                                                                                |
| FR-025 | P2       | Coordinate multi-repository changes without assuming atomic cross-repository merges.                                                                                                                                                                                                                                                                                                      |
| FR-017 | P2       | Track related PRs across repositories as a logical change set with dependencies and merge status. _(Was P1.)_                                                                                                                                                                                                                                                                             |
| FR-058 | P2       | Support dependency-aware multi-repository change sets with explicit handling of partial merges. _(Was P1.)_                                                                                                                                                                                                                                                                               |
