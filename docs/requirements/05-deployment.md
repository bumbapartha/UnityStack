[← Requirements](README.md)

Builds, environments, images and releases.

**Tools:** [CI/CD](../tools-and-adapters.md#cicd), [Container registry](../tools-and-adapters.md#container-registry), [Feature flags](../tools-and-adapters.md#feature-flags)

**Decisions:** [TD-01](../decisions.md#td-01), [TD-04](../decisions.md#td-04), [TD-08](../decisions.md#td-08), [TD-10](../decisions.md#td-10)

## Requirements

| ID     | Priority | Requirement                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| FR-097 | P0       | Deploy the managed project's walking skeleton (Hello World first) automatically through its CI/CD pipeline to staging and production environments on AWS from the start. UnityStack itself may run locally ([AD-6](../decisions.md#ad-6)).                                                                                                                                                                                                  |
| FR-130 | P0       | **New.** When a managed project first reaches deployment, ask the user for its deployment target (cloud provider, account connection, region, environments such as staging and production) through the AI workspace; keep credentials in a secrets store, never in Git or prompts; reach the cloud through a deployment adapter (AWS first) with least-privilege access.                                                                    |
| FR-129 | P1       | **New.** Deploy each PR of a managed project to its own preview environment for testing, in addition to staging and production.                                                                                                                                                                                                                                                                                                             |
| FR-044 | P0       | Version tests, CI/CD pipelines, deployment configuration and monitoring configuration in Git. _(Was P1.)_                                                                                                                                                                                                                                                                                                                                   |
| FR-045 | P0       | Run validation and deployment through trusted pipelines with environment protection. _(Was P1.)_                                                                                                                                                                                                                                                                                                                                            |
| FR-119 | P0       | **New.** Publish built images of managed projects to the artifact registry through its adapter, tagged with version, commit SHA and Change ID. _(Was P1.)_                                                                                                                                                                                                                                                                                  |
| FR-121 | P1       | **New.** Control feature exposure through feature flags reached via the OpenFeature SDK, with per-environment settings; flag changes are audited.                                                                                                                                                                                                                                                                                           |
| FR-098 | P0       | Support configured automatic delivery or human production release approval with quality gates. _(Was P1; production approval is part of the MVP loop.)_                                                                                                                                                                                                                                                                                     |
| FR-134 | P0       | **New.** After each release, generate and update the product's user documentation: Playwright runs capture screenshots of each screen, and the AI writes or updates the user guide from the stories and acceptance criteria, as Markdown in Git through a PR. Only pages touched by the release change. MkDocs builds an internal version with requirement links and a public version without them, published as a site or exported to PDF. |
| FR-135 | P0       | **New.** Let people comment on a screen or page of the user documentation; a comment can become a new requirement linked to that screen and its original requirement, and enters the loop at the requirements stage.                                                                                                                                                                                                                        |
